# Foundry handoff

1. Read the [roadmap checklist](ROADMAP.md) and pick the next agreed item.
2. Check live branches, open PRs and recent Actions results before retrying or applying changes. An earlier successful run establishes what passed in that run.
3. Compare the [Foundry product catalog](../registry/product-catalog.json) with the [published Ecosystem registry](https://github.com/sunstriker2009/sun-ecosystem/blob/main/registry/products.json) as needed. Foundry allocates IDs for new product registrations. Ecosystem publishes identities and supplies the live membership check for branding. The product repository holds its local identity in `branding/manifest.json`.
4. For interrupted work, inspect the existing run summary, artifacts and pending PRs. Follow the recovery steps for that operation in the [workflow handbook](WORKFLOWS.md) and record the verified result in the [roadmap](ROADMAP.md).

Use the normal SUN PR and approval process for operational changes. Development schedules are managed independently of this handoff.
